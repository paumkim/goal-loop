# Performance Investigation

Investigate <symptom> in this project, such as a slow command, high CPU or memory, or startup time, and define what better means. Measure a repeatable baseline, then profile or instrument the hot path to find where time and work are actually spent. Make the smallest change that targets the measured bottleneck while preserving observable behavior and public APIs. Re-measure with the same method and report before and after numbers, with no claims that lack evidence. Run relevant tests, typecheck, lint, and build, and explain any tradeoff in memory or complexity.
