Install and use

Viewing these docs

This site is static HTML/CSS with no build step and no internet. Double-click docs/index.html in your file manager, or run xdg-open docs/index.html from the repo root. Keep the whole docs/ folder together — pages use relative links.

Install

npm i -g @el4cteo/opencode-goal
opencode-goal install

That is the whole first-time setup. opencode-goal install registers the plugin in your global opencode config and tells you to restart opencode; the plugin then loads on the next start of both the TUI and the server. Requires OpenCode ≥2.0.29 and Node (or Bun) for the installer itself. The installer has zero runtime dependencies.

Uninstall

opencode-goal uninstall

Removes exactly what the installer added and leaves opencode as it was. If the config file the installer created is left empty, it is deleted. opencode-goal uninstall --restore copies the newest .bak back over the config instead (taking a fresh backup first).

The other subcommands

opencode-goal            # same as install
opencode-goal status     # scope, config path, installed yes/no
opencode-goal install --project    # the cwd's project config instead of global
opencode-goal install --dry-run    # show what would change, write nothing
opencode-goal --version

--global (default) and --project are mutually exclusive. --project targets the current directory's opencode config (discovery order opencode.json, opencode.jsonc, .opencode/opencode.json, .opencode/opencode.jsonc — first existing wins; ./opencode.json is created when none exists).

What the installer touches

One file: the config opencode itself picks. Global: $XDG_CONFIG_HOME/opencode/opencode.jsonc, or ~/.config/opencode/opencode.jsonc when XDG is unset (opencode.json wins when only it exists; opencode.jsonc is created when neither exists). Every file is backed up before writing (<file>.<yyyy-MM-DD-HH-mm-ss>Z.bak, never overwritten). Only the plugins array is edited; comments, formatting and unrelated keys survive. The run is idempotent: a second install prints already installed and exits 0; an uninstall with nothing to do prints not installed and exits 0. Writes never leave the target scope, and the installer never opens your config by hand.

Prefer doing it yourself? Add "plugins": ["@el4cteo/opencode-goal"] to your opencode config, or point plugins at a local clone: { "plugins": ["/path/to/opencode-goal"] }. The installer exists so you do not have to.

Commands

CommandAction
/goal <condition>Set goal and start immediately
/goalShow status
/goal clearRemove goal (aliases: stop, off, reset, none, cancel)
/goal-loop <objective>Set a goal; each achieved goal arms an improved one until maxLoops, LOOP_COMPLETE, an impossible verdict, or clear
/goal-loopShow loop status (objective, iteration, history)
/goal-loop clearEnd the loop (same aliases as /goal clear)
/goal-loop make the docs site faster and more complete

The loop advances only on a met verdict; each iteration is summarized into a short machine-consumable block and the evaluator proposes the next goal under a strict contract. Pause reasons and resume rules are the same as /goal, plus: an armed /goal-loop never pauses at the turn cap or the stall guard — a one-time warning notice is emitted and the loop keeps running; its stops are Esc, a fatal provider error, or /goal clear; zero-tool-call iterations are recorded but never pause the loop; the loop keeps arming with a fresh compacted context each version.

/goal bun test passes with 0 failures and no test file is modified

opencode.json options

{
  "plugins": [{
    "package": "@el4cteo/opencode-goal",
    "options": {
      "evaluator": { "model": "opencode-go/deepseek-v4.1-flash" },
      "maxTurns": 0, "stallTurns": 0, "checkinMinutes": 30,
      "maxRetries": 3, "requireCommit": true, "commitBranch": "dev", "coordinator": "auto"
    }
  }]
}

Full table: Config. In coordinator repos (term) coordinator: "auto" (default) switches normal agents to wt/<slug> + submit / merge-next instead of a direct dev commit; true forces it, false disables it. merge-next lands the oldest submitted lease on dev and blocks unless bun run check passes on the merged result (a branch whose merge is the fix for a failing gate is merged, not rejected) (packages/coordinator/bin/coordinator merge-next).

Troubleshooting

Pause reasons

For plain goals: only your interrupt (Esc), or an explicit maxTurns cap you set yourself (default 0 = off), pauses the goal — a message then cannot extend the cap until /goal clear or a new goal. An armed /goal-loop does not pause at the maxTurns cap or the stallTurns stall guard (one notice each, the loop keeps running). Terminal provider errors (auth 401/403, credit 402, context 413, model 404, quota exhaustion) fail the goal instead of waiting. Rate or usage limits are retried every 15 minutes forever; transient failures use capped exponential backoff forever; zero-tool iterations and evaluator crashes never pause (src/runtime/controller.ts, README.md).

Failed recovery

Fatal errors (auth 401/403, credit 402, context 413, model 404) fail the goal (status failed, distinct from cleared). Fix the cause, run /goal again; sending a message does not resume a failed goal (src/core/errors.ts:49, src/runtime/controller.ts:665).
