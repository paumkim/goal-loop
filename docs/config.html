Configuration

Options live in opencode.json under plugins[].options. Precedence is env var > option > default. Prompts (directive, loopContinuation, summarize*, nextGoal*) live in src/core/prompts.ts.

Set evaluator.verifyCommand for development loops. Without it, the plugin never reruns your check (e.g. bun run check) before accepting a met verdict. An armed dev loop loses the one deterministic guarantee the plugin offers.

Probe mode: OPENCODE_GOAL_PROBE=1 makes plugin storage read-only, so goal records are never written or removed and restore() has no side effects. The verification command still executes in the probe's working directory. Use it for probe or scratch opencode servers. bun run check also runs bun scripts/spec-check.ts (check:spec). It asserts the machine-readable <!-- spec-check files=N tests=N --> marker in SPEC.md matches npm pack --dry-run --json and the bun test pass count.

The defaults table is DEFAULTS in src/core/config.ts. Resolution is resolveConfig() in src/core/config.ts. Env OPENCODE_GOAL_REQUIRE_COMMIT accepts 1/true/yes/on and 0/false/no/off (envBool in src/core/config.ts). Coordinator detection uses detectCoordinator in src/core/git.ts, called from resolveCommitPolicy in src/core/git.ts. Detection holds when both .term/coordinator/config.json and .term/coordinator/state.json exist. It also holds when the coordinator bin exists (project packages/coordinator/bin/coordinator or an absolute plugin bin) and at least one of the two json files does. config.json may set devBranch and worktreeDir. OPENCODE_GOAL_COORDINATOR accepts auto/1/true/yes/on/0/false/no/off (parseCoordinator in src/core/config.ts). Prompts and rubric per mode live in src/core/prompts.ts (coordinatorFlow, commitStatusSuffix, rubric, facts — all in src/core/prompts.ts).
