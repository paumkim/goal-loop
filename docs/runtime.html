Runtime

Turn loop

Each turn ends → the controller snapshots the epoch, counts tool calls, checks background work, then evaluates the condition. not_met sends a continuation steer prompt; for /goal-loop goals met goes to the loop step instead of finishing; otherwise met/impossible finish the goal (src/runtime/controller.ts:266, src/runtime/controller.ts:358).

/goal-loop improvement loop

/goal-loop <objective> is the same machine with a post-met step: the achieved iteration is compacted into a short machine-consumable summary (max(200, maxLoopSummaryTokens) × 4 char cap), the evaluator generates the next goal (single condition, or exactly LOOP_COMPLETE) and arms it under the same rules. Guards: maxLoops (default 5) completed iterations ends as achieved; LOOP_COMPLETE or an unusable generation ends cleanly as achieved; impossible ends the loop as today; two consecutive zero-tool-call iterations pause; evaluator failures pause after maxRetries. Per-iteration info toasts (kind: "loop"), one achieved toast at the end. Loop state (loopEnabled, loopIteration, loopObjective, loopHistory, loopNotProgress) lives on the record and survives restore.

Auto-compaction

With compactAtTokens > 0, the plugin asks the host to compact the session after a turn when the estimated model-visible context (last assistant input + cache.read + cache.write, src/core/context-size.ts:38) reaches the threshold. An in-flight or recently requested compaction is not re-requested (src/runtime/compactor.ts:27).

Epoch invalidation

A per-session epoch is bumped by new turns, user prompts, clears, and replaces. Stale async results are dropped (src/runtime/controller.ts:39, src/runtime/controller.ts:759, src/runtime/controller.ts:767).

Background defer and idle check-ins

If subagents or background shells still run, evaluation defers and arms check-ins: first after checkinMinutes, then doubling up to 4×. Max idle check-ins default 3 (src/runtime/controller.ts:608, src/runtime/controller.ts:620, src/core/config.ts:44).
